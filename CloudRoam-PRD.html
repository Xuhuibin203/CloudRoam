01背景与目标

手机应用普遍索取精确定位并持续上报：社交、外卖、地图、广告 SDK 均以真实位置为输入。对隐私敏感用户而言，"不给定位权限"往往意味着功能不可用，"给权限"则意味着真实行踪被记录。

CloudRoam 的产品响应是：整机级的位置伪装——用户自选一个虚拟位置，开启后所有读取定位的应用只能拿到该虚拟位置及其配套环境数据（卫星、WiFi、基站），关闭后立即恢复真实定位，无任何残留标记。技术上选择注入式伪装（root + LSPosed 模块）而非系统自带的"模拟位置"通道，因为后者自带可被识别的模拟标记，且不覆盖 WiFi 与基站数据源，无法满足"所有 APP"这一要求。

可观察目标

编号目标（可验证的观察结果）
O1作用域内任意应用读取的位置均为虚拟位置，包括"最后已知位置"类缓存读取。
O2卫星信号、WiFi 扫描结果、基站信息与虚拟位置一致，交叉验证不暴露真实位置。
O3关闭后，目标应用在下次读取时即恢复真实数据，无需重启目标应用；模拟标记无残留。
O4所有开关入口（应用内、通知栏、快捷磁贴）状态一致；任何异常（服务被杀、模块失效）自动回落到"关闭"安全态。

02产品契约

要素定义
主用户已完成 root 并安装 LSPosed 框架的 Android 个人用户，用途为保护个人位置隐私。
触发用户产生隐藏真实位置的需要：日常使用社交与生活服务应用、将手机短暂交由他人使用、开发调试定位相关功能等。
核心工作选择虚拟位置 → 开启伪装 → 正常使用其他应用 → 关闭并恢复真实位置。
完成条件开启时：作用域内应用读到虚拟位置（O1/O2）；关闭时：立即恢复真实位置（O3）。全程不需要重启目标应用。
信任边界仅用于隐私保护等合法用途。首次启动必须阅读并同意用户协议；协议明确禁止平台作弊（网约车/外卖、考勤、游戏等）与违法行为，违规责任由使用者承担。
运行环境root 权限 + LSPosed 框架 + CloudRoam 模块已激活。【假设，待定】最低 Android 版本：Android 9+，需技术验证。无该环境时提供降级的兼容模式（FR-10）。

03范围

P0 —— 最小完整旅程

入口：完成环境自检 → 选点 → 开启 → 作用域内应用读到虚拟位置 → 关闭 → 恢复真实并自动记入历史。以下能力为 P0：

  • 环境自检与分步引导（root / LSPosed / 模块激活 / 作用域）
  • 地图选点（拖图、POI 搜索、长按）与位置库（收藏、历史）
  • 三种模拟模式：单点、路线模拟、摇杆
  • 定位欺骗引擎：位置 API、卫星信号、WiFi 扫描、基站、模拟标记隐藏（FR-05）
  • 作用域管理：白名单制（默认）/ 全局模式
  • 开关生命周期：应用内开关 = 通知栏 = 快捷磁贴，关闭即恢复，失败安全
  • 国产 ROM 保活引导（自启动、电池白名单）
  • 用户协议与首次启动合规确认

P1 —— 支持能力

  • 定时自动关闭、地理围栏自动关闭
  • 免 root 兼容模式（能力上限见 FR-10）
  • 出口 IP 归属一致性提示（仅提示，不内置代理）
  • 气压计海拔、时区一致性

明确排除

账号体系与云端同步、小程序 / Web 远程遥控端、iOS 版本、多任务并行伪装、伪装日志导出。【假设，待定】免费 / 付费模式未定，见开放问题；当前文档不包含任何付费墙行为。

版本规划

版本内容验收锚点
M1 核心链路环境自检引导、地图选点、位置 API 伪装、开关生命周期、用户协议微信"发送位置"、地图应用显示虚拟位置；关闭立即恢复
M2 深度伪装WiFi / 基站 / 卫星伪装、模拟标记隐藏、三模式、作用域管理、保活引导主流应用交叉验证不暴露真实位置（O2）
M3 体验与兼容定时 / 围栏自动关闭、兼容模式、IP 一致性提示P1 清单全量可用

P0 = M1 + M2；P1 = M3。分发渠道：官网 APK 直接安装与 LSPosed 模块仓库，不走应用商店。

05功能需求

FR-01 环境自检与引导 P0

目的：让用户在开启引擎前确认四项运行前提全部就绪，避免"以为开了其实没生效"。

触发：首次启动自动执行；设置页可手动重新检测。

规则：以四步清单逐项检查并实时刷新状态——① root 权限；② LSPosed 框架已安装；③ CloudRoam 模块已激活；④ 模块作用域已启用。每项未通过时给出对应操作指引（图文步骤），并提供"重新检测"。

结果：全部通过 → 进入首页，引擎可开启；任一未通过 → 引擎开关置灰，显示缺失项摘要，用户仍可浏览地图与位置库。

例外：无 root 环境长期存在时，引导页提供降级入口指向兼容模式（FR-10）。

FR-02 地图选点与搜索 P0

布局：首页为全屏地图（高德地图服务），顶部搜索栏，底部为位置卡（当前虚拟位置 + 模式 + 主开关）。

选点方式：拖动地图使中心大头针对准目标；搜索结果点选；长按任意位置选点。

规则：选定后位置卡立即显示坐标与逆地理地址（需联网）；选点精确到建筑级；搜索关键词返回 POI 列表（名称 + 地址 + 距当前位置远近排序）。

例外：搜索无结果 → 空态提示并建议更换关键词；逆地理解析失败 → 仅显示坐标；网络不可用 → 选点仍可用（坐标有效），地址栏显示"暂无（离线）"。

FR-03 位置库：收藏与历史 P0

触发：位置卡"收藏"按钮存入收藏；引擎每次关闭自动写入历史。

规则：收藏与历史分 Tab 展示；任一条目点击即设为当前虚拟位置并回到首页；历史记录包含结束原因，便于回溯。

例外：位置库为空时显示引导空态（"选一个位置并收藏，下次一键开启"）。

FR-04 模拟模式 P0

模式行为规则
单点 坐标恒定不动。 叠加 GPS 级自然抖动与合理精度值（精度半径 8–25m）【假设，待定】，避免"完美静止"暴露。
路线模拟 地图上取起点与可选途经点，按步行 / 骑行 / 驾车速度档沿道路行进。 速度符合所选档位（含路口减速）；到达终点后保持静止，"往返"为可选项；路径规划失败时降级为直线慢速插值并提示。
摇杆 屏幕虚拟摇杆控制方向与速度。 摇杆幅度映射速度（步行至驾车范围）；松手即缓停。

共享规则：任何模式下禁止位置瞬移；位移速度不超过当前档位上限；运行中切换模式时位置保持连续（图 2"模式切换"）。

FR-05 定位欺骗引擎 P0

目的：使作用域内应用从任何数据源读取到的都是与虚拟位置一致的伪装数据。这是产品核心，其余模块全部服务于它。

生效机制（用户可感知口径）：开启引擎后，CloudRoam 通过系统框架注入作用域内的目标应用进程，在数据源头改写读取结果；关闭后直接放行原始数据。目标应用无需重启。

伪装数据源清单

数据源完整模式下的表现版本
位置读取（GPS / 网络 / 融合）全部返回虚拟坐标，包括"最后已知位置"类缓存读取。M1
卫星信号（GNSS / NMEA）呈现真实接收状态：卫星数量、信噪比、分布与虚拟位置一致，不出现"零卫星的完美定位"。M2
WiFi 扫描结果返回虚拟位置附近的接入点集合（底料在开启时经地图位置服务获取并本地缓存；离线时沿用上次缓存）。M2
基站信息返回虚拟位置所在区域的合理小区数据。M2
模拟标记目标应用读取到的"是否模拟位置"恒为否，无法据此识别。M2
出口 IP 归属仅检测并提示与虚拟位置不一致（FR-11），不自动改写。P1

处理规则：

  • 配置读取：注入层实时获取当前任务与开关状态；开关关闭、应用不在作用域、或配置通道异常时，一律直接放行原始数据。
  • 即时生效：开启后，目标应用的下一次位置读取即为虚拟数据；系统层"最后已知位置"缓存同样被改写。
  • 性能约束：伪装不得产生可感知的卡顿、耗电异常或位置更新延迟；数据生成按需计算，不做高频重算。

已知限制（如实告知用户）：部分应用自带进程内定位缓存或自建定位通道，可能需重进页面后刷新；出口 IP 不在伪装范围内（P1 仅提示）。应用内"已知限制"页固化此清单。

FR-06 作用域管理 P0

默认：白名单制。作用域页列出已安装的用户应用（排除系统应用与 CloudRoam 自身），用户勾选生效对象。

模式生效对象确认方式
白名单（默认）勾选的用户应用应用内勾选后，引导用户确认框架侧作用域与勾选一致；不一致时给出修正步骤。
全局全部用户应用切换时二次确认（警示影响面），并同样做框架侧一致性校验。

规则：CloudRoam 自身永不生效；系统核心组件不可勾选；引擎运行中修改作用域即时生效，无需重启目标应用。

FR-07 开关与生命周期 P0

唯一真值：引擎状态只有一个，所有入口操作同一状态，任意入口切换后其余入口即时同步。

入口位置行为
主开关首页底部位置卡开启 / 关闭引擎；开启前置校验：环境自检通过且已选点。
常驻通知通知栏（运行中出现）显示当前虚拟位置与时长；提供"关闭"操作；不可被侧滑清除，仅关闭操作可移除。
快捷磁贴下拉快捷设置单击切换引擎；磁贴外观区分运行 / 关闭。

关闭与恢复：任意入口关闭 → 停止伪装 → 注入层放行 → 通知移除 → 写入历史（结束原因 = 手动）→ 位置卡回到"真实位置"态。定时 / 围栏触发的自动关闭走同一链路，结束原因相应标记，并经通知告知"已自动恢复真实位置"。

FR-08 用户协议与合规 P0

  • 首次启动展示用户协议与用途声明，必须明确同意后才能使用任何功能；协议版本更新后需重新确认。
  • 协议内容：仅限隐私保护等合法用途；禁止用于网约车 / 外卖等平台作弊、考勤造假、游戏作弊及一切违法违规场景；违规造成的后果由使用者承担。
  • 设置页可随时查看协议全文与历史确认记录。

FR-09 自动关闭策略 P1

策略参数行为
定时关闭15 分钟 / 1 小时 / 自定义（5 分钟–24 小时）开启时可设置；到点自动关闭并通知。
围栏关闭以真实位置为圆心，半径 500m / 1km / 5km / 自定义设备真实位置离开围栏即自动关闭并通知；用于"忘关兜底"。

两种策略互斥，同一任务只允许一种；自动关闭优先于运行中状态，触发后结束原因写入历史。

FR-10 免 root 兼容模式 P1

触发：环境自检无法通过（无 root 或无 LSPosed）时，提供降级方案，走系统"模拟位置应用"通道。

能力完整模式兼容模式
位置读取伪装✓（含缓存）✓（基础）
WiFi / 基站 / 卫星伪装✓✗
模拟标记隐藏✓✗（可被应用识别）
前置条件root + LSPosed开发者选项手动指定 CloudRoam

切换到兼容模式时，应用内必须明示上述能力差异，由用户确认后启用。

FR-11 IP 一致性提示 P1

引擎开启时检测出口 IP 归属地与虚拟位置的距离；明显不一致时在首页展示提示条，说明"部分应用可能通过 IP 推断真实位置"及可选的自理方式（如自行连接目标城市网络）。仅提示，不内置、不代理、不强制。

06共享规则

规则定义
状态唯一引擎仅"关闭 / 运行中"两态；模式是运行中的子属性。任何入口读到的状态一致。
失败安全任何异常都回落到"关闭"：放行真实数据、移除通知、写入历史（异常兜底）。伪装永不残留。
数据保留历史滚动保留最近 100 条【假设，待定】；收藏无上限；全部仅存本地，无任何云端上传。
结束原因枚举手动 / 定时到点 / 触发围栏 / 异常兜底，四个取值，历史与通知共用。
通知规范运行中通知不可侧滑清除；"关闭"是移除通知的唯一途径；自动关闭由系统通知告知结果。
隐私底线CloudRoam 自身不采集、不上传任何位置与使用数据；选点、历史、协议确认全部本地保存。
